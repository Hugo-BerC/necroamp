# ADR 0006: Media protocol, media CSP and audio pipeline
- Status: Accepted provisionally under the user's autonomous engineering authorization, subject to human review of the PR. No human approval has been given. Open decisions 4 and 5 stay open until the human reviews the PR. Amends ADR 0003 (new scheme privileges, `media-src`).
- Related: `tech.md` "Audio engineering rules" and "Filesystem access is mediated by main", ADR 0003, ADR 0005, `docs/requirements/audio-engine/`.

## Context
The renderer must play local files and seek without receiving paths or filesystem access. `app://renderer` serves only five renderer file types and must stay that way. A `media-src 'none'` CSP blocks all playback today.

## Options
| Option | Correctness | Simplicity | Reversibility | Security |
|---|---|---|---|---|
| A. `HTMLMediaElement` + `MediaElementAudioSourceNode` over a `media://` protocol with Range | Good seeking, streams large FLAC | Simple | High | Narrow if token-gated |
| B. Main reads whole file, sends bytes over IPC, renderer `decodeAudioData` | Gapless-friendly | High memory for FLAC, large IPC payloads | Medium | Bytes cross IPC |
| C. `file://` or `blob:` URLs | Works | Simple | High | Breaks ADR 0003 origin rules, exposes paths |

## Decision
1. **Option A.** One hidden `HTMLAudioElement` in `renderer/audio/` is the source, connected to the Web Audio graph in `tech.md`.
2. **Scheme.** `media`, registered before `ready` with `standard`, `secure`, `stream`, `supportFetchAPI` and `corsEnabled`. Never `bypassCSP`. `corsEnabled` is required because a cross-origin media element feeding `createMediaElementSource` outputs silence unless the response is CORS-approved. The element sets `crossOrigin="anonymous"` and responses send `Access-Control-Allow-Origin: app://renderer` (the exact trusted origin, never `*`; the dev origin only in a dev run).
3. **URL form.** `media://track/<token>`. The host is the fixed constant `track`. The token is a random 128-bit value generated by main (`crypto.randomUUID`). The URL never contains a path.
4. **Authorization registry** in `src/main/library/`. Main maps `token -> real path`. Tokens are created only for (a) files the user picked in the main-process open dialog, and (b) entries of a playlist loaded from main-owned persistence, re-checked with `stat` on load. The registry holds at most 5000 tokens, is cleared on window close, and tokens are never accepted from the renderer as paths. The renderer cannot ask for a path to be served.
5. **Handler** (`protocol.handle('media', ...)`, pure parsing in a testable module). `GET` and `HEAD` only. Rejects any host other than `track`, unknown or malformed tokens, credentials, query, fragment, extra path segments. Allows extensions `.mp3 .wav .flac .ogg` (also `.oga`) only. Resolves the real path and requires a regular file. Parses a single `Range` (`bytes=a-b`, `a-`, `-n`) and answers `206` with `Content-Range`, `Accept-Ranges: bytes`, or `416` for unsatisfiable ranges. Multi-range falls back to `200` full body. Reads with `fs.createReadStream` (no `net`). Every rejection returns `404` with no rule name. Headers: `Content-Type` from the extension map, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, `Cross-Origin-Resource-Policy: cross-origin` limited by the CORS header above.
6. **Open decisions.** 4 (pipeline) is resolved here to Option A pending human confirmation; gapless playback is NOT promised. 5 (metadata) proposes `music-metadata` in main, license and size recorded at install; the version is resolved from the registry, never guessed. `music-metadata` is adopted provisionally, only if its license and bundle size are acceptable when checked at install. Both remain **needs human decision** for final closure at PR review.
7. **CSP.** Production changes from ADR 0003 are `media-src media://track` and `img-src 'self' media://art`. Nothing else changes (`default-src`, `connect-src`, `worker-src`, scripts stay). No `blob:` or `data:` source is added. Album artwork is extracted in main, validated (PNG, JPEG or WebP by magic bytes, at most 2 MiB), cached in memory under a random token, and served read-only as `media://art/<token>`. The same handler enforces the token gate for both hosts (`track`, `art`).
8. **AudioWorklet.** Not used. `BiquadFilterNode`, `GainNode` and `AnalyserNode` cover EQ, preamp, volume and visualization. `worker-src` stays `'none'`. A later ADR is needed if a worklet becomes justified.
9. **Sender and IPC.** Each new channel goes through `registerHandler` (ADR 0005), has `strictObject` Zod schemas in `src/shared/ipc`, bounded sizes, and no path in any renderer-bound payload. Channel list is in the design document.

## Consequences
- Seeking and large files use streaming and Range, with no whole-file IPC.
- A second scheme and a CORS-enabled privilege widen the protocol surface. Mitigation: token gate, extension allow list, exact origin, `404` for all rejections, unit and property tests for the parser.
- Whether `createMediaElementSource` outputs audio over this scheme and whether Chromium accepts the `206` stream is unverified until a runtime test runs. If CORS fails, the fallback is Option B, which needs a new ADR.
- Packaged-build behavior on macOS and Linux is not verified.
- Automated tests can prove data flow (analyser non-zero on a synthetic tone). They cannot prove that sound is audible. That needs human listening.

## Rejected
- Option B now (memory, IPC size). Option C (breaks ADR 0003). Path-based URLs (`media://?path=`). Serving any file the renderer names. `webSecurity` relaxation.
