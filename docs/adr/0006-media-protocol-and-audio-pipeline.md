# ADR 0006: Media protocol, media CSP and audio pipeline
- Status: Accepted provisionally under the user's autonomous engineering authorization, subject to human review of the PR. No human approval has been given. Open decisions 4 and 5 stay open until the human reviews the PR. Amends ADR 0003 (new scheme privileges, `media-src`).
- Related: `tech.md` "Audio engineering rules" and "Filesystem access is mediated by main", ADR 0003, ADR 0005, `.kiro/specs/audio-engine/` (canonical Spec; `docs/requirements/audio-engine/` only points to it).

## Context
The renderer must play local files and seek without receiving paths or filesystem access. `app://renderer` serves only five renderer file types and must stay that way. A `media-src 'none'` CSP blocks all playback today.

## Options
| Option | Correctness | Simplicity | Reversibility | Security |
|---|---|---|---|---|
| A. `HTMLMediaElement` + `MediaElementAudioSourceNode` over a `media://` protocol with Range | Good seeking, streams large FLAC | Simple | High | Narrow if token-gated |
| B. Main reads whole file, sends bytes over IPC, renderer `decodeAudioData` | Gapless-friendly | High memory for FLAC, large IPC payloads | Medium | Bytes cross IPC |
| C. `file://` or `blob:` URLs | Works | Simple | High | Breaks ADR 0003 origin rules, exposes paths |

## Decision
1. **Option A.** One hidden `HTMLAudioElement` in `renderer/audio/` is the source, connected to the Web Audio graph in `tech.md`. The graph and its `AudioContext` are created lazily on the first play gesture (`ensureReady`) and built once per element.
2. **Scheme.** `media`, registered before `ready` with `standard`, `secure`, `stream`, `supportFetchAPI` and `corsEnabled`. Never `bypassCSP`. `app` and `media` are registered in a single `registerSchemesAsPrivileged` call (`registerPrivilegedSchemes` in `src/main/protocol/register-schemes.ts`), because Electron keeps only the last call and a second call would silently drop the `app` privileges. `registerMediaScheme` exists for tests only. `corsEnabled` is required because a cross-origin media element feeding `createMediaElementSource` outputs silence unless the response is CORS-approved. The element sets `crossOrigin="anonymous"` and responses send `Access-Control-Allow-Origin: app://renderer` (the exact trusted origin, never `*`; the dev origin only in a dev run).
3. **URL form.** `media://track/<token>`. The host is the fixed constant `track`. The token is a random 128-bit value generated by main (`crypto.randomUUID`). The URL never contains a path.
4. **Authorization registry** in `src/main/library/`. Main maps `token -> real path`. Tokens are created only for (a) files the user picked in the main-process open dialog, and (b) entries of a playlist loaded from main-owned persistence, re-checked with `stat` on load. The registry holds at most 5000 tokens, is cleared on window close, and tokens are never accepted from the renderer as paths. The renderer cannot ask for a path to be served.
5. **Handler** (`protocol.handle('media', ...)`, pure parsing in a testable module). `GET` and `HEAD` only. Serves hosts `track` (audio) and `art` (item 7) and rejects any other host, unknown or malformed tokens, credentials, query, fragment, extra path segments. Allows extensions `.mp3 .wav .flac .ogg` (also `.oga`) only. Resolves the real path and requires a regular file. Parses a single `Range` (`bytes=a-b`, `a-`, `-n`) and answers `206` with `Content-Range`, `Accept-Ranges: bytes`, or `416` for unsatisfiable ranges. Multi-range falls back to `200` full body. Reads with `fs.createReadStream` (no `net`). Every rejection returns `404` with no rule name. Headers: `Content-Type` from the extension map, `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, `Cross-Origin-Resource-Policy: cross-origin` limited by the CORS header above.
6. **Open decisions.** 4 (pipeline) is resolved here to Option A pending human confirmation; gapless playback is NOT promised. 5 (metadata) proposes `music-metadata` in main, license and size recorded at install; the version is resolved from the registry, never guessed. Installed at install time: `music-metadata` 13.0.1 (MIT, ESM-only, pure JavaScript, no install scripts). Its runtime dependencies are `@borewit/text-codec` 0.2.3 (MIT), `@tokenizer/token` 0.3.0 (MIT), `content-type` 3.1.1 (MIT), `debug` 4.4.3 (MIT), `media-typer` 2.0.0 (MIT), `strtok3` 10.8.0 (MIT), `token-types` 6.2.0 (MIT; an earlier revision of this ADR recorded BSD-3-Clause in error, corrected per Gate B finding D-B2 after checking the installed package and `pnpm licenses`) and `win-guid` 0.2.1 (MIT). Because the main build is CommonJS (ADR 0002 section 6) and `music-metadata` is ESM-only, `electron.vite.config.ts` bundles it into the main output (`externalizeDeps.exclude`) instead of requiring it at runtime. The bundle adds about 0.35 MB of parser chunks under `out/main`. `music-metadata` is pinned exactly at 13.0.1 in `package.json` and adopted provisionally. Both open decisions remain **needs human decision** for final closure at PR review. Test tooling: `wasm-media-encoders` 0.7.0 (MIT wrapper; compiled libvorbis/libogg BSD-3-Clause and LAME LGPL) is a devDependency used only by `tests/fixtures/audio/generate-vorbis.ts` to build an Ogg Vorbis fixture. It is not imported from `src/` and is absent from `out/` (see `docs/engineering/audio-engine-dependency-review.md`).
7. **CSP.** Production changes from ADR 0003 are `media-src media://track` and `img-src 'self' media://art`. Nothing else changes (`default-src`, `connect-src`, `worker-src`, scripts stay). No `blob:` or `data:` source is added. Album artwork is extracted in main, validated (PNG, JPEG or WebP by magic bytes, at most 2 MiB each), cached in memory under a random token (`crypto.randomUUID`), and served read-only as `media://art/<token>`. The same handler enforces the token gate for both hosts (`track`, `art`). **Status: implemented in Block B (feature/audio-engine).** `src/main/security/csp.ts` is the single source: production is `img-src 'self' media://art` and `media-src media://track`; the `<meta>` copy and the development policy derive from the same directive list, and development changes only `script-src`, `style-src` and `connect-src`. No `blob:` or `data:` source exists. `art` tokens live in a separate in-memory store (`createArtworkStore`) from `track` tokens (a token from one namespace never resolves in the other), identical images (SHA-256 digest) are stored once, and the cache is capped at 5000 entries and 64 MiB in total; a `put` over any cap returns no token and the track shows the placeholder. The media type comes from the sniffed magic bytes, never from the tag's declared MIME type, so a JPEG labelled PNG is served as `image/jpeg`. Art responses are `GET`/`HEAD` only, `200` with `Content-Length`, no `Range`, with the same `nosniff`, `no-store` and CORS headers as audio. The store is cleared when the main window closes, together with the registry. The renderer receives only `media://art/<uuid>` URLs (`artworkUrlSchema`), never bytes or paths.
8. **AudioWorklet and graph.** AudioWorklet is deliberately not used. `BiquadFilterNode`, `GainNode` and `AnalyserNode` cover EQ, preamp, volume and visualization. `worker-src` stays `'none'`. A later ADR is needed if a worklet becomes justified. Graph (`src/renderer/audio/graph.ts`): source -> 10 biquads -> preamp `GainNode` -> master `GainNode` -> `AnalyserNode` -> destination, with topology fixed after construction. Volume and mute are the master gain, clamped to `[0, 1]` (never a boost), smoothed with `setTargetAtTime`. Until the graph exists (before the first play), the engine applies volume and mute to the element itself; once the graph exists the element is fixed at `volume = 1`, `muted = false` so the level is applied once, not twice.
9. **Sender and IPC.** Each channel goes through `registerHandler` (ADR 0005), has `strictObject` Zod schemas in `src/shared/ipc`, bounded sizes, and no path in any renderer-bound payload. As built: `library:open-files`, `library:resolve-track`, `playlist:load`, `playlist:save`. No `settings:*` channel exists (see the Audio Engine spec, C4).

## Consequences
- Seeking and large files use streaming and Range, with no whole-file IPC.
- A second scheme and a CORS-enabled privilege widen the protocol surface. Mitigation: token gate, extension allow list, exact origin, `404` for all rejections, unit and property tests for the parser.
- Verified on Windows by E2E: Chromium plays the `media://` stream with Range, and the analyser shows a non-zero tone through `createMediaElementSource` (CORS path works, so Option B is not needed). Decoded formats: WAV, MP3, FLAC, Ogg Vorbis (real Vorbis fixture) and Ogg FLAC.
- Not verified: macOS and Linux decoders, the packaged build on any platform, Ogg Opus.
- Automated tests prove data flow (analyser non-zero on a synthetic tone). They cannot prove that sound is audible. That needs human listening (gate H.2).
- `media://` is registered on the default session and tokens live until the window closes. The Skin Engine must not load untrusted web content in that session (security review AE-04).

## Rejected
- Option B now (memory, IPC size). Option C (breaks ADR 0003). Path-based URLs (`media://?path=`). Serving any file the renderer names. `webSecurity` relaxation.
